═══════════════════════════════════════════════════════════════════════════════
 WHY THIS SCRIPT WORKS
═══════════════════════════════════════════════════════════════════════════════

  Old approach (FAILED):
    DELETE FROM licenses;
    ↓
    ERROR! Batches still reference licenses via license_id!

  New approach (SUCCESS):
    1. First: UPDATE batches SET license_id = NULL
       (Remove all FK references)
    2. Then: DELETE child tables (documents, transactions, events)
    3. Then: DELETE license_requests
    4. Finally: DELETE licenses
       (No FK violations because references removed!)


═══════════════════════════════════════════════════════════════════════════════
 WHAT HAPPENS TO BATCHES?
═══════════════════════════════════════════════════════════════════════════════

  Batches are NOT deleted!

  Only the license_id column is set to NULL:
    Before: batch.license_id = 'f4d519bf-...'
    After:  batch.license_id = NULL

  This means:
    ✓ All your batch data is preserved
    ✓ Weights, statuses, dates - all kept
    ✓ Only the link to licenses is removed
