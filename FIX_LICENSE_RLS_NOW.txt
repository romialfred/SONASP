  Step 2: Find table: "license_requests"

  Step 3: Delete these policies:
    • "Factory and management can create license requests"
    • "Users can view license requests"
    • "Users can update their draft license requests"

  Step 4: Create NEW policy:
    Name: Authenticated users can create
    Command: INSERT
    Target: authenticated
    WITH CHECK: true

  Step 5: Create another policy:
    Name: Authenticated users can view
    Command: SELECT
    Target: authenticated
    USING: true

  Step 6: Repeat for table: "license_request_documents"

 🔍 WHY THIS HAPPENED
═══════════════════════════════════════════════════════════════════════════════

The original migration (20251108000000_create_export_license_system.sql)
created very strict RLS policies that only allow specific roles.

These policies assumed:
  • Your user has role='factory' OR role='management'
  • Your user_profiles table is populated
  • Role-based access control is fully configured

Reality:
  • User roles may not be set up yet
  • Testing needs less restrictive policies
  • You need to submit requests NOW
